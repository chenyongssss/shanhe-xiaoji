# 轻量自部署版方案

## 目标

让用户 fork 或下载项目后，不需要后端，也能部署一份自己的旅行地图。每个人可以维护自己的城市、照片、标签、攻略和路线，并通过公开链接展示。

## 推荐形态

轻量版保持纯静态：

- GitHub Pages、Vercel、Netlify 均可部署。
- 数据默认保存在浏览器本地。
- 支持 JSON 导出和导入，用于迁移设备或迁移到公开站点。
- 不依赖登录、数据库和服务器函数。
- 照片可随导出文件迁移，但大量照片更适合后续云存储版。

## 用户流程

1. 用户 fork 仓库或下载模板。
2. 修改 `config.json` 中的站点名称、简介、默认地图数据等配置。
3. 部署到 GitHub Pages 或 Vercel。
4. 打开自己的站点，录入旅行地点。
5. 使用“导出数据 / 导入数据”迁移本地内容。
6. 分享自己的公开网址。

## 轻量版需要补齐的能力

### 1. 模板配置

新增 `config.json` 可选字段：

```json
{
  "siteTitle": "我的旅行地图",
  "siteSubtitle": "把去过的地方做成一张旅行主页",
  "ownerName": "旅行者",
  "defaultMapName": "我的中国旅行灵感图",
  "seedDataUrl": "./data/starter-map.json",
  "apiBaseUrl": "",
  "mapId": "default",
  "accessToken": ""
}
```

轻量版只使用展示配置和 `seedDataUrl`。`apiBaseUrl` 等字段保留给云同步版。

### 2. 初始数据

支持用户把自己的默认地图放到：

```text
data/starter-map.json
```

首次打开站点时，如果本地没有数据，就加载这份初始地图。

### 3. 数据迁移

当前项目已经具备：

- 导出数据
- 导入数据
- 本地保存
- GitHub Pages 静态部署

下一步要优化：

- 导入前显示城市数量预览。
- 支持“覆盖 / 合并”两种导入模式。
- 导入完成后提示用户当前数据只保存在这个浏览器里。

### 4. 外部平台内容导入

轻量版不直接抓取平台内容，避免授权和版权风险。推荐做成“用户主动导入助手”：

- 粘贴小红书链接：保存来源链接。
- 粘贴正文：自动提取地点、标签、预算、路线和避坑点。
- 上传截图：后续用 OCR 提取文字。
- 上传图片：作为地点相册。

第一阶段可以先做“粘贴正文生成地点卡”，不碰平台爬取。

## 开发阶段

### 阶段 A：模板化

- 让 `config.json` 控制站点标题、副标题、地图名称。
- 增加 `data/starter-map.json` 初始数据加载。
- README 增加 GitHub Pages 部署教程。

当前已完成：

- `config.example.json` 增加 `siteTitle`、`siteSubtitle`、`ownerName`、`defaultMapName`、`seedDataUrl`。
- 页面标题、品牌名、品牌副标题、顶部地图名支持运行时配置。
- 增加 `data/starter-map.example.json` 作为初始地图样例。
- 首次打开且本地无数据时，可从 `seedDataUrl` 自动加载初始地图。

### 阶段 B：导入助手

- 新增“从攻略文本生成地点”入口。
- 从文本中提取地点名、标签、攻略正文。
- 允许用户确认后写入地图。

### 阶段 C：展示优化

- 增加公开展示模式。
- 隐藏编辑控件，只保留地图、地点卡、相册和路线。
- 支持一键复制公开链接。

### 阶段 D：云同步升级

- 接入 Supabase 或 Firebase。
- 图片上传到云存储。
- 用户登录和多设备同步。
- 地图可设置公开、私密或协作。
